# 匿名发现的隐私与威胁模型

本文对应交友模块 Phase 1。系统向参与者提供的是**对其他参与者的身份隐藏**。阿里云运维方、数据库管理员、认证服务和邮件供应商有各自可见的数据。匿名连接、端侧摘要和 TLS 各自提供不同的保证。未实现的双向暗恋和语义匹配列在后半部分，不能作为当前版本的产品承诺。

## 数据经过哪里

- 设备持有用户输入的邮箱、收到的一次性验证码、会话令牌、生成或粘贴的共同口令，以及用户主动提交的发现信息。完整邮箱和邮箱用户名只用于自己的账户。匿名页面和匹配 API 不向对方返回这些标识。共用设备、键盘、屏幕录制、截图、分享渠道仍可能看到输入。
- 自托管 Supabase Auth 与邮件投递系统处理邮箱和验证请求。独立的匹配 RPC 使用被验证的登录会话获取身份，检查邮箱已验证和发现功能的成年声明。邮箱验证证明当时能够收邮件，不能证明法定身份、年龄、当前设备使用者或现实关系。限额按账户执行，不能单独防住多邮箱注册。
- PostgreSQL 的受限 schema 处理账户标识、粗略区域、时间窗、出行距离、场所、同意状态、相等令牌、关联账户和举报。成员只能调用规定的 RPC，不能列举底表。配对、撤回、屏蔽、删除在事务内串行。拥有数据库管理权限的人仍可访问这些数据。需要隔离数据库、限制运维角色和备份解密权限。
- 匿名连接内的消息在双方设备和服务端以可读形式处理。第一次匿名通信不要求公开照片或身份，但用户自行发送的姓名、地址、单位、图片链接仍可能识别本人。现有学习版的 DeepSeek 图像识别独立运行，参与匹配不授权发送口令、聊天内容或身份给 DeepSeek。

## Phase 1 的口令协议

客户端用系统安全随机源生成 16 字节，再编码为带版本和校验码的字符组。双方可通过自行选择的可信渠道事先交换。用户必须主动提交，双方提交即同意在匹配成功后建立匿名连接。软件不要求把内容复制到系统剪贴板。

1. 只接受协议规定的 ASCII 字符。全角 ASCII 折回半角，英文字母不区分大小写，忽略分组连字符和指定的 Unicode 空白。拒绝其他文字、零宽字符、混淆字形、缺位和校验失败。校验码只帮助发现抄写错误。
2. 将 16 字节原始值与固定版本域前缀组合，经 SHA-256 生成匹配令牌。校验码和匹配令牌使用不同的前缀。发送令牌与幂等请求编号，原始值不进入匹配数据库。协议的固定测试向量在 `test/secret_code_test.dart`。
3. 服务端再对接收的令牌进行带独立域前缀的 SHA-256，只存储用于等值查询的二次摘要，过滤自己、已屏蔽双方、已有连接和过期意愿。每个成员同时只能有一个等待请求，一次匹配消耗双方意愿。有第三人拿到口令时，该人可以先于预期对象参加。两个新账户再次使用一个历史口令仍可能彼此匹配，因此应为每次约定生成新口令。
4. 等待最久 24 小时，每个账户每 UTC 固定日窗最多成功创建 8 次新请求。令牌在匹配成功或撤回时清空，未消费的过期令牌不能参与匹配，下次清理时擦除。已停止且无连接的意愿元数据在其截止时间过去 30 天后由维护任务清理。账户层只保留幂等编号摘要等防重放凭据直到认证账户删除，清除发现资料后旧提交不会恢复。
5. 令牌本身具有持有者凭据的效果。请求链中泄露的有效令牌可能被另一账户提交。仅泄露等待表的二次摘要不能直接用作请求令牌，但仍可关联相等项、离线试验已知口令。服务端能观察相等关系、账户、匹配时间、IP 元数据和连接，不能从一段 64 位十六进制文本判断其输入是否确由安全随机源生成。随机性来自符合协议的客户端；恶意客户端可直接提交自选摘要。不要用普通文本、生日、学校、姓氏或现实记忆替代随机生成。

## 需要防御的场景

| 场景 | 当前约束、泄漏边界与后续控制 |
| --- | --- |
| 字典攻击和离线穷举 | 随机口令有 128 比特随机性。对生日、学校名等小集合，攻击者可枚举摘要，固定盐和公开前缀都不能保护它们。服务端持有的 HMAC 密钥只抵挡未取到密钥的副本入侵者，不能抵挡同时控制在线服务的人。Phase 1 不收这些字段。 |
| 单向发现、进度和地点推断 | 本人能看见等待和自己收到的匿名提议；另一人操作时带来的状态改变可透露参与时间。只在双方确认后返回精确地址和约定时间。测试和真实地点分开；测试地点不能安排真实见面。熟悉本地店铺的人仍可能从非常小的场所池猜出地点，正式运营需扩充已复核的地点和时段并审查稀疏区域。已经展示的地址不能从记忆或截图中收回。 |
| 冒充和批量探测 | 身份从验证后的会话取得，不信任客户端传入账户。显示给自己的邮箱名可与他人重名，所有授权使用账户 UUID。猜到请求编号也不能操作别人的参与记录。应用层成功请求配额限制创建速率，失败事务会回滚计数，边缘服务仍需限制失败流量、OTP 滥发、IP 段和设备批量注册，并验证没有邮箱存在性探针。 |
| 并发重试、重放和旧状态 | 服务端事务锁、唯一约束和幂等编号防止重复连接；读取前验证参与资格；到期不能配对。重复确认不能代替另一人的同意。屏蔽对双方、两个入口都有效，按认证身份保留，删除发现资料后重开也生效。重新注册一个新的认证账户是另一种攻击，需配合举报处置。 |
| 线下跟踪与恶意邀约 | 只收区域参考点，不收家庭地址、轨迹或实时 GPS。距离依据审核的参考点数据；个人实际通勤会不同。审核记录需要覆盖场所开放、可达性及营业时间，维护者必须复查闭店或暂停服务。支持取消、屏蔽、举报。邮箱与成年自述不能排除危险行为，公开运营前需要场所值守、举报工单、人工处置和紧急求助流程。 |
| 恶意运维、备份与撤回 | 私有 schema、RLS、最小 RPC 授权保护普通请求。拥有数据库、Auth 签名密钥或邮件权限的人可能关联社交图、冒充身份或读取消息。管理员访问需审计，备份加密、分权、设置独立 TTL；恢复后重放删除和封禁记录。撤回影响之后的查询，用户已读取的信息及备份淘汰窗口要在正式隐私说明中写明。 |
| 日志与统计泄漏 | 不记录 OTP、邮箱、JWT、原始口令和令牌、聊天内容、账户配对、地点、时间窗、原始请求体或完整响应。反代/WAF、Supabase Auth、PostgREST、PostgreSQL 参数日志、错误追踪、第三方崩溃录屏各自需要明确配置与抽查。只保留不含输入的错误类别、成功数、延迟。HTTP 集成测试可在本地两个服务日志中搜寻本次生成的敏感标记。测试不能证明尚未部署的阿里云日志系统已经脱敏。 |

服务端授权与数据期限详见 [匹配架构](matching-architecture.md)。正式运营前应在实际网关、自托管 Auth、数据库、SMTP、日志和备份恢复链上重复审查。用于买量、广告和学习产品的分析 SDK 不应收到交友行为事件。

## Phase 2：双向暗恋优先

**产品状态**：尚未提供暗恋入口。随机口令协议不能证明输入者正是某个被暗恋对象。

- **身份绑定。** 仅接受用户已验证的自有邮箱账户发起；目标需指定固定格式的身份（首版可选完整邮箱）。匹配必须同时满足 A 指向经验证的 B、B 指向经验证的 A。服务端绑定稳定账号而非邮箱前缀，并明确邮箱变更、回收、别名和重新验证策略。未经验证的自述姓名不参与校验。不要跨域一律折叠大小写、点号、加号别名。防止自指。不推送“有人喜欢你”，无论目标存在、被屏蔽或只提交单边，统一显示“已记录”，不返回候选数量。
- **次数和撤回。** 建议按首次成功提交时刻起滚动 365 天计算，一次提交原子写入独立的账号配额凭据和选择记录。匹配、撤回、封禁、修改邮箱或发现资料重新开通均不返还该名额。提交前展示确认页，提交后随时撤回。撤回后消除活动选择和未送达通知；另一方先前读过的消息无法回收。重试同一个客户端请求不能第二次扣费或计次。彻底删除认证账号与防止重新注册绕过年度额度之间有冲突；仅保留经评估的最少反滥用数据并告知期限，多邮箱绕过要单独衡量。
- **增强条件。** 双方都没选增强项时按双向身份匹配；双方都选时，类型、版本和规范值都必须相同；只一人填写或答案不同时保持原来的等待状态，不退回弱匹配。用固定格式，例如约定见面的年月，或者双方事先约定的随机口令。约定哪一个人的生日，区分是否包含年份、时区、精度，不做模糊猜测。日期容易被熟人猜中，界面必须告知其作用是缩小条件。允许用户选择真正随机的增强项。除非双向成功，不披露哪一个条件失败。
- **身份索引隔离。** 最小可行试验可在独立的身份解析服务持有密钥，将规范身份转换成版本化、用途隔离的索引，并隔离选择库和身份映射库。该方案能保护部分数据库泄露，但解析服务仍接触目标邮箱，必须明确告知。更强候选是限流且独立部署的 VOPRF 服务。其盲化覆盖求值时的输入；随后发送确定性结果用于匹配仍暴露相等关系，运营方串通、密钥失陷及授权客户端的在线枚举仍需测试。引入经审查实现、密钥轮换、盲化协议和隔离部署前保持关闭。[RFC 9497](https://www.rfc-editor.org/rfc/rfc9497)
- **生日、学校、姓氏等共同点。** 每个类别独立同意、语义、密钥和撤回；优先在已连接双方双向授权后仅显示“有共同点”。避免小组稀有值与精确生日的交叉反推。先明确被保护方、服务端能力和可接受的揭示，评估带速率限制的 PSI/VOPRF 或独立计算方。每人盐会破坏跨用户相等判断，跨用户通用盐会允许枚举。仅凭摘要不得推出可公开检索的低熵匹配服务。
- **通过门槛。** 自动化测试至少包含冒充身份、未验证邮箱、相同前缀不同账户、单向不可观察、增强项单边与不等、撤回和配对竞争、跨年边界、删除重开、阻止邮件存在性与屏蔽状态泄漏。统计只记不含配对明细的聚合，例如分母明确的参与数和双方同意比例；小样本抑制并限制切片，禁止展示真实个人的小组计数和伪造人数。渐进披露按字段和对象单独授权，支持撤回未来展示。

## Phase 3：语义匹配的隐私档位

**产品状态**：尚未下载语义模型、上传描述或向用户展示相似度结果。第一轮以明确选填的非敏感兴趣模板为限。相同秘密令牌仅支持相等测试，不能用于近似匹配。

| 档位 | 可计算内容 | 明确告知和试验要求 |
| --- | --- | --- |
| A，用户同意上传端侧向量 | 端侧分词、Embedding 和归一化；服务器按相同模型版本索引向量，计算余弦相似度并提名，再双向同意。 | 服务器得到可读向量，能推断某些原文内容与兴趣。HTTPS 或磁盘加密不能消除这一风险。允许拒绝、不输入、撤回并清除索引和缓存。仅在独立用户明确选择 A 时启用。 |
| B，用户同意上传有限签名 | 端侧对同一模型输出做版本化随机超平面投影，上传 LSH 位串。服务端按桶或汉明距离近似检索。 | 签名会泄漏相似关系、分布和成员信息，已知描述可投影对比，LSH 不是加密。控制签名长度、近邻数、查询配额和模型/投影版本；评估召回、近似偏差、成员推断。B 仅发布签名，不以原始向量回查 A 档用户。 |
| C，安全计算研究 | 可信执行环境可以在经证明的受限环境内解密。独立计算方可研究秘密共享或 MPC；同态加密可在兼容密钥和参数下对加密向量计算内积。 | 普通随机化加密后的向量无法直接用常规向量库计算余弦。跨用户密钥兼容、结果解密、阈值比较、Top-K、候选预筛、访问模式和恶意参与者都需专门协议。TEE 信任硬件、远程证明和运维，MPC 的串通假设和 HE 的计算开销必须量化。客户端选“仅本机/需安全计算”时不回退为上传向量。 |

端侧模型和分词器应固定来源、许可证、文件校验与版本。服务端不得跨版本直接比较向量。用获得授权或合成的样本在离线测试中记录正负样本、Recall@K、误配率、不同兴趣语种差异、内存、时延和电量。成功门槛还应包括对样本的成员推断与恢复实验、验证删除后不再命中、双向同意前不回显他人描述，以及一键关闭试验。公开运营时的 A/B 试验另行取得参与同意。[Embedding 反演研究](https://aclanthology.org/2023.emnlp-main.765/) · [Microsoft SEAL 的同态运算能力与限制](https://github.com/microsoft/SEAL)
