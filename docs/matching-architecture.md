# Chenbot 匿名发现架构

## 现有项目与改造范围

本次以 GitHub 的 main 提交 `466e355` 为基线。Android 与 iOS 共用 Flutter，原有识图、阅读、难度测试、生词本和发音均有自己的客户端逻辑。照片、词库和学习记录保存在用户设备。用户选择识图时才会直接请求 DeepSeek。旧 Node 识图桥仅供本机开发。此前已有 Supabase Flutter 邮箱验证码代码及钱包、交易、收藏表的初始迁移，应用内充值、商店验单和跨设备学习同步仍属后续工作。

新增底部「发现」入口，沿用现有页面字体、卡片和颜色。交友使用同一邮箱登录会话，复用设备安全存储与应用导航。交友匹配不会使用学习历史、照片、模型密钥或钱包。没有服务器配置时，应用如实显示配置状态。Phase 1 已实现下文的报名、配对、同意、匿名消息与安全操作。Phase 2、3 目前均为后续任务。

## 登录、系统边界与请求流

1. Flutter 使用公开的项目 key，通过 HTTPS 向自托管 Supabase Auth 申请邮箱数字验证码。同一验证流程支持新账号和再次登录，验证通过才有认证会话。手机按服务地址隔离保存会话。
2. 本人看到的名称取已验证邮箱中 `@` 之前的部分。名称可以重名，服务端以认证 UUID 识别本人。匹配对象只看到匿名连接。年龄门槛为单独的 18 岁以上自我声明，邮箱验证码只证明当次可访问邮箱。
3. 网关仅公开必要 Auth 路由与列出的 PostgREST RPC。PostgREST 校验 JWT，数据库从 `auth.uid()` 取得调用者并复核已验证邮箱。客户端无法指定以谁的身份匹配。数据表位于私有 `matching` schema，启用 RLS 并撤销客户端表权限。公开函数受限于认证角色、空 search_path、显式所属关系与状态检查。
4. 匹配与安全操作在数据库事务中完成。状态读还会清理过期资格，或为等待者重试配对。打开页面后会定时刷新，也能手动刷新。提议通过应用内状态送达，当前没有离线推送。上海自托管部署路径、SMTP 与清理任务见[部署手册](matching-deployment.md)。

## 两种发现方式

**Blind Encounter**。用户从上海五个区域参考点中选择一个，给出时间窗、距离上限和私密的场所氛围偏好。服务端接受未来 20 分钟之后、未来 30 天内、跨度 1–8 小时的窗口以及 1–50 公里的上限。可达距离使用运营维护的参考点到场所估值，无需用户当前位置。按排队先后寻找双方都能到达且营业时间重叠至少一小时的场所，从不同合格场所中随机选一个。已屏蔽、已连接者和已占用时段不参与。没有候选人或没有合格场所时继续等待。

两人分别收到提议。提议最晚在 24 小时或约见前 5 分钟到期，取较早者。单人确认只改变本人的同意标记。双方确认后才可取到具体时间、店名和地址。任一方可取消。预约的一小时结束后隐藏地址，双方可各自确认见面结束、选择继续；双方均完成这两步才建立线上连接。会后窗口在预约开始后三天结束。完成状态是本人自述。界面不会跟踪用户行程或验证是否真的到场。

生产目录须有人审核公共属性、可达性、营业日、营业时间和复核截止时间。生产初始无地点。测试夹具中的虚构地点与生产有不同的开关和标志。修改场所或距离会使相关未结束提议重新检查或取消。场所接入边界在 `blind_eligible_venues` 和 `blind_options`，以后可以替换供应商或增加节假日、路线和多个营业时段，继续履行同一筛选和披露契约。

**Secret Match · 花样年华**。用户在本机生成 128 位安全随机口令，经双方自行选择的渠道分享。另一方输入同一口令，各自明确选择加入并同意匹配后开启匿名连接。客户端对有限字符集做全角折叠、大小写与空白处理，检验输入校验码，计算用途隔离的 SHA-256 令牌。服务端对收到的令牌再计算独立用途的摘要，按相等关系查找仍有效且没有屏蔽关系的等待者，在同一事务中消费两条请求。端侧不上传原始口令。令牌在传输时具有持有者凭证的作用；服务端仍能观察参与者、时间及相等关系。获知口令的第三人也可能先配对。应为每次相遇生成新的口令。生日、姓氏、邮箱或人写的短句需要不同协议。详见[隐私威胁模型](privacy-threat-model.md)。

## 数据字典与生命周期

除运营维护的场所目录外，下面的身份、报名、关系、地点选择、消息、举报、配额和请求标识都属于敏感业务数据。全部禁止进入请求日志、崩溃附件和个人级分析。上线监控只使用与个人无关的健康状态和汇总时延。运维身份、邮件服务和数据库备份有单独的权限与生命周期。数据库所有者可以读取匹配数据和聊天正文。

| 数据表 | 字段用途与唯一性 | 可见范围、有效期、删除行为 |
| --- | --- | --- |
| auth.users / matching.members | Auth UUID、验证邮件；成员以 user_id 为主键，attested_at 记录同意成年声明的时刻 | 邮箱归本人和认证服务使用。删除发现资料移除成员资格；Auth 账户继续可登录既有应用。删除 Auth 用户会级联清理成员 |
| blind_areas / blind_venue_policy | 区名主键、出行参考点；单行策略控制生产或虚构目录 | 区名与参考点可展示；目录写入限可信运营。策略持续有效直到更换 |
| blind_venues / blind_reach | 场所 UUID、名称地址、氛围、营业时间和星期、公共性、可达性、审核和有效期；每个场所与区唯一一条公里数 | 场所审核到期自动退出候选。地址仅在双方确认后的会面窗口披露。删除场所级联删除距离。运营维护目录可长期保存 |
| blind_requests | 每人持有独立请求 UUID、账号、nonce、区域、起止、距离、氛围、meeting、状态、两个同意位和时间。每人 nonce 唯一，同时最多一个活动请求 | 只读本人投影。撤回/过期后停止参与，结束后 31 天清理，删除发现资料级联清理本人记录 |
| blind_meetings | 随机会议 UUID、场所、确定的开始时间和确认截止时间；两个个人请求引用同一会议 | 仅服务端访问。审批前不返回地点或准确时刻。无请求引用时清理 |
| secret_requests | 随机请求 UUID、账号、nonce、等待索引、状态、截止时刻、可空连接 ID。每人 nonce 唯一且最多一个等待索引 | 只投影本人状态。等待最多 24 小时，匹配、撤回或过期时清空索引。无有效连接的终态记录在截止时间再过 30 天后清理，成员删除时级联清理 |
| connections | UUID、排序后的两个成员 UUID、来源和创建时间；每对成员最多一条连接 | 双方只见连接句柄和来源。屏蔽、有效口令连接的撤回、删除资料或连接满 90 天时关闭 |
| messages | 随机 ID、连接、作者、发送 nonce、正文、时间；作者与 nonce 唯一 | 双方只见本人标记、正文、时间。每条 1–500 字符，显示近 30 天内最新 100 条。满 30 天清理，连接删除即级联删除 |
| blocks | 屏蔽人和被屏蔽人 UUID 构成联合主键，记录时间 | 匹配双向排除，没有公开名单。保留至相关 Auth 账号删除，发现资料重新开通后继续生效 |
| reports | 举报 UUID、提交人、对象、上下文类型和句柄、枚举原因、时间；每人每上下文最多一条 | 仅受信运营人工处理，保存 90 天。没有附加聊天或自由文本；Auth 删除会置空相应身份字段 |
| safety_contexts | 按本人、上下文类型和句柄唯一，保存原对方、来源、结束时间 | 近期记录仅给本人返回句柄、来源、类型和时间，最多 30 条。支持聊天关闭或对方删除发现资料后举报。31 天后删除，删除自己的发现资料会清理自己的历史，相关 Auth 账号删除则级联清理 |
| quotas / receipts | 每个认证账号和操作桶唯一，存窗口与计数；每个账号和操作 nonce 指纹唯一，不存提交内容 | 限流与防回放仅由服务端使用。配额窗口滚动替换；最小请求指纹保留至认证账号删除，防止旧请求在清理或重新开通后复活 |

实体定义、字段约束和索引以 `server/migrations/002_matching.sql` 至 `005_matching_safety.sql` 为准。业务删除影响在线访问；备份淘汰、恢复流程和云端日志需要另行验证。场所、账号、举报的运维写入必须使用独立的受信权限。

## HTTP API 与事务

使用 JSON POST 到 `/rest/v1/rpc/<函数名>`。每次带公开项目 key 和个人会话令牌。每个写操作从会话推导本人；下表的 ID 为返回给本人的请求或连接句柄。客户端遇到网络超时时应先用原 nonce 重试或查询当前状态。

| RPC | 请求 | 返回与约束 |
| --- | --- | --- |
| matching_me / matching_enroll | 无 / p_adult | 本人邮箱前缀、是否已开通；首次加入需明确传 true |
| blind_join / blind_state | p_area、p_start、p_end、p_distance、p_preference、p_nonce / 无 | 本人最新请求、状态、本人同意位。时间采用含偏移的时间戳，营业日按 Asia/Shanghai 解释 |
| blind_act | p_id、p_action，支持 confirm、complete、continue、cancel | 仅接受该用户当前合法的状态转换，返回经过披露检查的最新状态 |
| secret_join / secret_state | p_token、p_nonce / 无 | 返回 idle、waiting、connected、withdrawn 或 expired，等待时带到期时间，已连接时有匿名句柄 |
| secret_act | p_id、p_action=withdraw | 撤回自己的等待或已匹配的这次口令，关闭相关连接 |
| matching_connections / matching_messages | 无 / p_id | 本人的连接及来源 / 匿名消息列表 |
| matching_send | p_id、p_body、p_nonce | 同一有效消息的同载荷重试只写一次；相同 nonce 换有效正文会被拒绝 |
| matching_safety_history / matching_safety | 无 / p_kind、p_id、p_action、p_reason | 用所属的连接、见面或秘密请求上下文屏蔽或举报。举报原因可选 unsafe、harassment、impersonation、other。举报在同一事务内屏蔽并关闭连接 |
| matching_delete | 无 | 删除本人的发现资料和活动请求，立即撤销对方的相关会面及连接访问。保留独立的防滥用凭据与举报处理期 |

正式网关对白名单外路径拒绝访问。会员变更、报名、配对、读披露、屏蔽、撤回及维护通过同一 PostgreSQL 事务级 advisory lock 串行化，再由唯一约束兜底，避免并发时出现三人配对或在撤回后读取地址。当前单库全局锁适合小规模验证，要在公开运营前测量等待时间与吞吐；分片时须重新验证跨组屏蔽、删除和撤回。每账号采用固定时间桶，成功请求类操作预算 180 次/分钟，见面新报名 6 次/天，秘密新报名 8 次/天，消息 20 条/10 分钟，新举报 10 次/天。数据库错误会回滚本次事务内的计数，因此网关还需要对异常流量独立限流。端侧控制只用于交互体验。

## 开发验收与后续交付

- **Phase 1 复验**。按[本机联调](matching-local.md)启动独立数据库、真实 Auth、邮件收件箱和 PostgREST。用两个隔离会话走邮箱验证码、报名和匿名聊天。SQL 套件验证过期、撤回、黑名单、双向同意和数据删除，HTTP 套件验证跨账号授权与并发，Flutter 测试验证正常和异常页面。部署前还要在真实发信域名、网关、手机和非开发场所上复验。见[部署手册](matching-deployment.md)。
- **Phase 2a 双向暗恋**。设计稳定的验证身份作用域与邮箱变更流程。新增独立年度配额记录、定向选择和撤回 RPC。按一次成功提交起滚动 365 天计次，撤回不退额。只在 A 指向已验证的 B 且 B 指向已验证的 A 时建立连接。双向增强项必须同时缺省，或同时存在且类型、版本、规范化值完全相等。验收包括重提、换邮箱、并发撤回、同名前缀、仅单向以及仅一人填写增强项。对未注册或未回选目标统一返回收件状态，禁止单向通知。
- **Phase 2b 共同点与渐进披露**。按生日、学校等分别定义规范、目的、有效期和配额。先用独立身份解析边界做威胁评估，再试验经审查的盲化协议；生日、学校、姓氏的裸散列不能作为可公开查询的索引。先在已有连接中试行双向授权才揭示某个共同点。加入按连接、按字段、可撤回、带截止期的披露同意。仅在另行同意后开展有小样本抑制的聚合分析。上线门槛包括单侧不可观察、撤回后索引失效和低基数组合泄漏评估。
- **Phase 3 语义**。先选定可在 Android/iOS 端侧运行的模型、词表、许可与版本。对明确同意上传向量的用户做归一化余弦检索；对只同意有限签名的用户独立试验 LSH，并解释候选与相似性泄漏。普通密文无法直接送入常规余弦向量库。要求服务端只能计算密文的用户需等待带独立密钥与威胁模型的 HE/MPC 或经证明的受控执行方案。测试集采用获许可或合成描述，按语种测 Recall@K、误配率、端侧耗时和耗电；另测成员推断、撤回和阈值附近误判。通过离线和隐私评审后才开放可退出的小规模双向同意试验。各方案见[隐私威胁模型](privacy-threat-model.md)。
